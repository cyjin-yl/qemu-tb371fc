# XBL / SMEM bounded static evidence

These records describe limited static analysis of an existing, read-only
active-slot firmware backup. They are not an executed SBL, an authenticated
SMEM image or a successful original Android boot.

The original JSON and method/source blobs below are preserved byte-for-byte.
Their identities and evidence classes are listed in [manifest.json](manifest.json)
and [SHA256SUMS](SHA256SUMS). Original firmware payloads, certificates, complete
disassembly and private memory dumps are excluded.

## Evidence layers

| Layer | Original record | What it establishes |
| --- | --- | --- |
| Format metadata | [metadata.json](metadata.json) | Whole-archive/member integrity, bounded ELF/FV fields and allowed marker/literal candidates |
| A: pointer candidates | [pointer-xrefs-a.json](pointer-xrefs-a.json) | Sixteen known string locations searched across four non-executable LOAD ranges; two distinct pointer slots and eight mapped neighbouring candidates |
| B: candidate control flow | [control-xrefs-b.json](control-xrefs-b.json) | One 4 KiB candidate window, unchanged original slice hash, a passing BL/RET format control, explicit omitted-output counts |
| C: two candidate callees | [callee-xrefs-c-v2.json](callee-xrefs-c-v2.json) | Two 2 KiB windows; the original control and eight assertions over ten self-authored A64 words passed; 49 address candidates reported |
| Offline inference | [cfg-inference.json](cfg-inference.json) | A local graph derived only from already-exported candidates, stopping at unknown/omitted boundaries |
| Linux consumer ABI | [Markdown](linux-consumer-abi.md) and [JSON](linux-consumer-abi.json) | Source-derived offsets and acceptance conditions at a fixed third-party kernel mirror commit |

The consumer ABI uses commit
`9d8abebf4ac4d45cf4cc11b5b6bc5e4483d10fd1` of
`tem423/android_kernel_lenovo_tb371fc`; it does not establish that mirror as
the exact production source. The corrected ABI distinguishes the LE32
partition length at header offset +0x08 from the 32-byte header structure size.
Old, ambiguously named ABI blobs are not substituted for these corrected files.

## Method and reproducibility limits

[METHOD.md](METHOD.md) is the original collection/reproduction note.
The exact supporting texts are in [method/](method/):

- `metadata-wrapper.py`
- `pointer-wrapper.py`
- `control-wrapper.py`
- `followed-callees-wrapper-v2.py`
- `xbl_metadata.py`
- `archive_validation.py`

The four wrapper files are source bodies requiring injected
`PARSER_SOURCE`, `ARCHIVE_VALIDATOR_SOURCE` and
`WRAPPER_SOURCE_SHA256`. They are not standalone CLIs. The preparation-only
example in METHOD.md assumes the supporting files are the current directory.
The original parser also has a CT CLI; that file-writing path was not called
by the tablet wrappers.

Each collection opened only the existing archive with read-only/no-follow/
no-atime flags. Source and input hashes, 12 KiB output bounds and actual
truncation counts are retained. B/C passed derived in-memory analysis objects
to LLVM; the firmware was not executed. The synthetic analysis ELF header is
not the original firmware header.

The wrappers were not separately tested before their first collection runs.
The 12 earlier CT tests apply to the original parser only. B's three-word
control and C's additional controls cover the stated parser behavior, not all
A64 encodings or hardware equivalence.

## Remaining proof obligations

The records do not establish configuration-table layout, actual platform
selection, reachability from the real firmware entry, a complete function
boundary, the selected initializer values or actual writes to SMEM.
RX ranges may contain literal pools; a decoded candidate is not proof of
execution. Conditional paths remain alternatives.

The public Linux consumer checks are targets for an evidence-backed protocol
implementation. They do not justify setting initialized=1, inventing a version
or partition table, supplying dummy socinfo, or declaring remote firmware
services available. No SMEM handoff was generated by this work.

This archive was assembled from existing text evidence without a new device
read, model run or firmware execution. The current native full-DT failure is
recorded separately in
[the native-diagnostic summary](../ci-20261123-1208/native-progression.json).
